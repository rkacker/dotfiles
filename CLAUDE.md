# CLAUDE.md

Guidance for Claude Code when working in this repo.

## What this is

Personal macOS dotfiles managed with GNU Stow. Every top-level directory except `iterm2/`
is a stow package whose tree mirrors `$HOME`. `install.sh` is the single entry point and
must stay idempotent.

## Conventions

- Adding a config file: put it under an existing package at its `$HOME`-relative path.
  Adding a new package: create the directory and add its name to the `for pkg` loop in
  `install.sh`.
- Dependencies go in `Brewfile`, grouped under a comment header.
- `zsh/.zshrc` guards every `source` and `eval` behind an existence check so a fresh
  machine gets a working shell before `brew bundle` runs. Keep that pattern.
- `iterm2/com.googlecode.iterm2.plist` is generated by iTerm2. Don't hand-edit it; if a
  setting needs changing, change it in iTerm2 and commit the resulting diff.
- `claude/.claude/settings.json` is symlinked to `~/.claude/settings.json`; Claude Code
  writes to it directly, so unexpected diffs there are normal.

## Secrets

This repo is public. Never commit tokens, API keys, passwords, private hostnames, or
machine-specific values such as git identity or absolute home paths. Those go in
`~/.zshrc.local`, `~/.config/git/config.local`, or `~/.claude/settings.local.json`, all
gitignored. If a new machine-specific value is needed, add a prompt or env-var fallback
to `install.sh` that writes it to the matching local file. A gitleaks pre-commit hook in
`.githooks/` enforces this; don't bypass it with `--no-verify`.

## Verifying changes

```bash
zsh -n zsh/.zshrc && bash -n install.sh   # syntax
zsh -i -c exit                             # shell loads cleanly
plutil -lint iterm2/*.plist                # plist is valid
gitleaks git --pre-commit --staged .       # nothing secret staged
```
